# 開発依頼：わたしの記事路線図 / NOTE TRANSIT

このパッケージを読み、iPadで使える静的Webアプリを実装してください。企画書だけで終わらず、取り込み→路線図生成→編集→共有まで動かしてください。既存プロジェクトがあれば構成を確認し活かしてください。

## 目的と優先順位
自分のnote記事を、テーマ別の地下鉄路線図に変える。「あー、そんな感じね」「こんな接点があったんだ」と遊べて、自分の書いてきたことを少し振り返れるツールです。
1. 入力の少なさ。100記事を100回入力させない。
2. 路線図の美しさ、遊び心、記事へ寄り道する楽しさ。
3. URLで他の人が参照できる。
4. 記事傾向の簡単な振り返り。
分類の唯一の正解は求めません。ただし関係のない記事を完全ランダムで結ばず、実際の共通語や日時に根拠を持たせること。性格・能力の診断はしないでください。

## 必須制約
- 私はPCを持っていません。開発指示と確認はiPadのみ。SafariとiPhoneに対応。
- タッチで全操作可能。ホバー、右クリック、キーボード必須は禁止。
- バックエンド、データベース、外部AI API、ブラウザ内の生成AIモデル、APIキー、ログインは不要。
- HTML/CSS/JSと静的素材を配信する構成。静的ホスティングは使えるが、サーバーでの処理・ユーザーデータ保存は行わない。
- 依存ライブラリは必要最小限、配布物に同梱できる構成を優先。
- noteからのスクレイピング、非公式API、外部RSS変換サービスは使わない。
- 公開前提のリポジトリに個人のエクスポート原本や本文をコミットしない。

## 同梱物を確認
- samples_private/note_export_original.zip：ユーザー提供のエクスポート原本。公開11件・下書き3件を確認済み。開発時のローカル検証専用。
- docs/SAMPLE_REPORT.md：形式と期待値。本文は記載していない。
- assets/decor_atlas.png：背景透過の水彩装飾6点。
- assets/atlas.json：画像内の各装飾領域。必要ならこの範囲を切り出して個別PNGにするか、描画時のsource rectangleとして使用。
- assets/UI_SYMBOLS.svg：駅・乗換駅・延伸・路線のベクター記号。
- docs/ASSET_GUIDE.md：素材用途。
原本の中身を公開デモに直接埋め込まない。公開デモは架空の記事データで作る。

## 基本体験
初期画面に「noteのZIPを選ぶ」「サンプルで試す」。ファイルを選択すると端末内で解析し、公開記事数と除外数を示す。通常は数回の操作で最初の路線図ができる。全記事のタグ付けを事前条件にしない。

### 入力
noteエクスポートのZIPおよびXMLに対応。
- ZIP内のWXR XMLをnamespace-awareで解析。正規表現だけでXML全体を処理しない。
- content:encodedとexcerpt:encodedを混同しない。
- タイトル、link、post_id、post_date、status、本文、画像参照を読む。
- wp:status=publishだけを既定で採用。draft、予約、状態不明は除外して件数表示。公開共有に入れない。
- publishは有料記事を含み得る。本文・本文抜粋は共有へ自動出力しない。
- タイトル未設定、URL欠損、日付不明でもクラッシュさせず警告と修正導線を用意。
- URLは許可したhttpsリンクのみ。javascript/dataなどを拒否。
- 本文HTMLは文字列として解析し、スクリプト、iframe、外部画像を実行・読み込みしない。
- /assets/のローカル画像参照をZIP内ファイルへ対応付ける。先頭画像は「見出し画像候補」とし、正式な見出し画像と決めつけない。候補変更・非表示可能。
- 大きなZIPは画像を一括展開せず、XMLと必要画像を順次処理。ファイル数・展開後サイズの上限、進捗、キャンセル、わかるエラーを実装。

## AIを使わない分類
日本語の分割・正規化、TF-IDF等の特徴語抽出、類似度計算、クラスタリングを使う。形態素解析などの通常の文章処理は可。採用ライブラリの対応環境・ライセンスを確認。
- 表記ゆれを正規化。日本語の助詞、挨拶、定型フッター、URL断片などを弱める。
- タイトルを重視し、本文は補助。全記事に出るAIなどの語だけで全体を一つにしない。
- 長文が有利にならないよう正規化。
- 固定カテゴリだけに押し込まない。旅行・料理・日記など未知の話題でも動く。
- 記事数に合わせて少数の路線を提案する。1記事だけの孤立も許容。
- 各記事の主路線は1つ、副路線は通常1つまで。全駅が乗換駅にならないよう抑制。
- 路線の順序は原則日付順。編集可能。
- 命名は共通語＋テンプレート。例えば「ガチャ再販線」「つくってみた線」。根拠が弱ければ素直なキーワード名を使う。
- 各接点の理由として「共通語：資格・勉強」などを表示。生成した架空の引用や、意味を読んだふりをしない。

### 3つの遊び方
1. 話題でつなぐ：内容の共通語で路線を作る。
2. 時間でたどる：年月と投稿順で活動の移り変わりを見る。
3. 意外な乗換：異なる主路線の記事から、珍しい共通語のある接点を選ぶ。無関係なら作らない。
「別の路線図にする」で、候補語・路線数・接点を変える。入力とseedが同じなら同じ結果。お気に入り保存、前の図に戻る、再生成しても手動編集を勝手に上書きしないこと。

## 路線図の描画
正確な駅・線・文字・乗換記号はSVG等で描画する。画像生成した路線図を背景にしてクリックだけ重ねる実装は禁止。
- アイボリー背景、濃い文字、テラコッタ・青緑・山吹等の路線色。
- 横・縦・45度と丸い曲がり角を基本にする。
- 乗換駅は同じ記事IDを持つ単一駅として扱う。
- 線が交差しただけの場所に駅を描かない。乗換と交差を明確に区別。
- 原題とは別に編集可能な短い駅名を持つ。全文タイトルは詳細で読む。
- レイアウト時に文字の実寸を計り、ラベルと他の駅・線の重なりを減らす。
- 100記事を1画面に無理に詰め込まない。パン・ピンチ拡大、全体表示、路線フォーカス、検索で到達できる。
- 遠景では重要駅名を優先し、拡大すると他の名前を表示。駅数は偽らない。
- 小さな画面では詳細は下部パネル、iPad横向きでは右パネル。
- 装飾は空き領域に薄く配置。文字・線を邪魔せず、タッチを奪わない。
- ユーザー画像は選択駅や少数の主要駅に限定できる。100枚を同時デコードしない。

## 記事を参照する
駅をタップ→正式タイトル、公開日、所属路線、共通語、画像候補→「noteで読む」で元の記事URLへ移動。
路線の隣駅や乗換先を選ぶ操作も用意。意味のあるリンクはa要素にし、キーボードでも基本操作可能にする。

## URL共有：必須だが長さに限界がある
静的アプリの公開URLのフラグメントに、圧縮・base64url化した閲覧用データを入れる方式を実装する。例：公開URL/#map=v1....
- 共有対象は確認済み公開記事の駅名、原題、元記事URL、日付（任意）、路線、駅順・配置、seed、明示した共有設定だけ。
- 本文、抜粋、下書き、ローカル画像、添付ファイル、原本ZIPは含めない。
- 画像は既定の装飾を使う。画像なしでも美しい閲覧画面にする。
- 元記事URLを可逆に短く表現する場合は、自アカウント以外や独自ドメインも壊さず、往復テストする。
- 共有前に記事数・共有内容・URL文字数を表示して、生成済みURLをコピーできる。
- 受信側はURLだけから表示できること。作成者のIndexedDBがなくても動くこと。
- 閲覧モードを既定にし、編集は「自分用にコピー」を選んでから。
- 短いIDだけで共有できる架空の保存サーバーを実装しない。
- URLの長さはブラウザや共有先で異なる。万能の上限を断言しない。
- 製品上の保守的な目安（例：8,000文字、設定可能）を超えたら、路線別の共有／記事の絞り込み／閲覧用HTMLの保存を提案する。長いリンクを無言で壊して渡さない。
- 圧縮は暗号化ではない。リンクを知る人に共有内容が見えると簡潔に表示。
- 共有データのschema version、型、件数、展開サイズ、URLを検証し、壊れたリンクはエラーを出す。
- フラグメントを解析サービス等へ送信しない。
- URL生成には実際に配信した静的アプリのURLが必要。localhostや開発環境の一時URLを恒久公開URLとして案内しない。

## 自分の分析に少し使う
図と整合する、根拠が明確な指標のみ。
- 月別の投稿数。
- 路線ごとの記事数（複数所属を含むことを明示）、ユニーク記事総数。
- よく登場する特徴語。
- 最近の期間と以前の期間で増減したテーマ。少数データなら判断できないと表示。
- 複数テーマをつなぐ記事。
スキ数、PV、人気、読者の反応、性格をこのZIPから推測して表示しない。
分析は本人用の画面。共有には既定で含めず、含める場合は明示選択させる。

## 編集・保存・書き出し
- 路線名・色、駅名、所属、順番、駅位置の修正。
- 複数記事をまとめて移動できる。全件手入力は不要。
- 取り消し・やり直し、図を固定、再配置。
- 保存はIndexedDB。共有用設定と本人用本文を別のデータ構造にする。
- 端末内保存が消える場合に備え、編集用JSONの書き出し・復元。本文を含む場合は明示。
- ZIP再取り込み時はURL/IDで照合し、追加・更新を表示。修正した路線や駅名を保護。消えた記事は削除候補として確認。
- PNG/SVGの図として書き出し。PNGは駅がクリックできないことを説明。
- 閲覧用HTML書き出しはCSS/JS/必要データを自己完結させ、外部サーバー不要。原本本文を埋め込まない。HTMLファイルのiOSでの実行は環境依存なので、URL共有を主導線にし、未検証の開き方を保証しない。
- SVG/HTML書き出しでは文字列を安全にエスケープ。

## デモとテスト
公開デモは架空の日本語記事で、複数テーマ・長いタイトル・同名タイトルを含む。
実データ原本はprivate fixtureとしてのみ利用し、公開ビルドに混入させない。
検証すること：
- 同梱原本で公開11件採用、下書き3件除外、公開記事タイトル/URL欠損ゼロ、画像参照31件解決。
- contentとexcerptの同名ローカルタグを混同しない。
- 1件、11件、100件、300件（後者は合成データ）の配置・操作。
- 同じseedの再現性と、再生成の変化。
- 有効な共通語がない記事を無理につながない。
- 圧縮共有URLの往復、新規ブラウザ状態での閲覧、長さ超過の代替導線。
- 共有データ、HTML、PNG/SVGに下書き・本文・非表示記事が入らない。
- タッチ位置、ピンチ、縦横回転、画像書き出し。
- 壊れたZIP/XML、未知のstatus、不正URL、展開上限。
- 依存ライセンスとconsole error。
実施したテストと未実施を区別。iPad実機確認をしていなければ明記。
