# わたしの記事路線図 / NOTE TRANSIT

noteの記事を、テーマ別の地下鉄路線図に変える静的Webアプリです。
iPad・iPhone の Safari だけで、取り込み → 路線図の生成 → 編集 → URL共有 までできます。
サーバー処理・データベース・ログイン・外部AI・APIキーは使いません。ファイルは端末の中だけで解析します。

## noteからZIPを受け取る手順

アプリのはじめの画面の「noteからZIPを受け取る手順」でも、画像つきで確認できます。

1. Safariで note.com にログインし、右上の自分のアイコン →「記事」を開く。
2. 「自分の記事」一覧の上にある「エクスポート」を押し、エクスポートを開始する。
3. 登録メールアドレスにお知らせが届くのを待つ（数分〜数時間。迷惑メールフォルダも確認）。
4. メールのリンクから「エクスポートファイルのダウンロード」画面を開き、「ダウンロード」（3回まで・期限つき）。
5. 「ファイル」アプリの「ダウンロード」に保存されたZIPを、展開せずにこのアプリの「noteのZIPを選ぶ」で選ぶ。

ZIPには有料記事を含む本文や下書きも入っているので、ZIPそのものは人に渡さないでください。

## iPadでの初回操作

1. noteの「設定 → 記事のエクスポート」で届いたZIPを「ファイル」アプリに保存しておく。
2. 公開URL（GitHub Pages）をSafariで開く。
3. 「noteのZIPを選ぶ」→ ZIPを選ぶ。公開記事数と除外数（下書き・予約など）が表示される。
4. 「路線図をつくる」。初回は数回のタップで路線図ができます（事前のタグ付け不要）。
5. 駅をタップ → 正式タイトル・公開日・所属路線・共通語・見出し画像候補 → 「noteで読む」。
6. 上部の「話題でつなぐ／時間でたどる／意外な乗換」で遊び方を切り替え。↻（別の路線図にする）で候補語・路線数・接点が変わります（前の図・履歴・お気に入りに残り、メニューから戻せます）。編集・画像保存・振り返りは右上のメニューから。

操作はすべてタッチで完結します：ドラッグで移動、ピンチで拡大縮小、＋/－/全体表示ボタン、路線チップで路線フォーカス、虫めがねで駅検索。

ZIPがなくても「サンプルで試す」で架空の記事（24件）の路線図を試せます。

## 他の人に見せる（共有）

右上の「共有」を押すと「他の人に見せる」が開きます。見せ方は2つです。

| | ① リンクで見せる（おすすめ） | ② 画像で見せる |
|---|---|---|
| 駅を押してnoteの記事へ | できる | できない（ただの画像） |
| 画像カード（見出し画像） | 入らない（リンクは文字だけ） | 入れられる（選択式） |
| 貼れる場所 | noteの記事・SNS・メッセージ | noteの記事・SNS |

noteで紹介するなら、②の画像を記事に貼り、そのすぐ下に①のリンクを貼るのがおすすめです。

メニューの「ファイルに保存（自分用・パソコン用）」（SVG・PNG・閲覧用HTML・編集用JSON）は、手元に残したりほかのアプリで使ったりするためのファイルです。人に見せるだけなら「共有」で足ります。

1. 「リンクをコピー」または「共有シート」で送る。受け取った人はURLを開くだけで閲覧できます（相手の端末に保存データは不要）。
2. 受け取った側は閲覧モードで開きます。編集したいときは「自分用にコピー」。
3. 範囲（全体／路線ごと）や含める内容は「リンクの設定」で変えられます。

- 共有データは `公開URL/#map=v1.…` のフラグメントに、圧縮＋base64url化して入っています。`#` 以降はサーバーへ送られません。
- 含めるもの：駅名・原題・元記事URL・路線・駅順・配置・seed・共有設定（日付・意外な乗換・振り返りは選択式）。
- 含めないもの：本文・抜粋・下書き・図から外した記事・画像・添付・原本ZIP・本文由来の共通語。
- 圧縮は暗号化ではありません。リンクを知っている人は上記の内容を見られます。
- URLの長さの上限はブラウザや共有先で異なり、一律の保証はできません。既定の目安は 8,000文字（メニューで変更可）。超えた場合は「路線ごとに共有」「記事を絞る」「閲覧用HTMLを保存」を提案します。
- リンクを貼ると、noteやSNSのリンクカードにアプリ共通のサムネイル（assets/og.jpg、デモの路線図）が出ます。サーバーがないため、路線図ごとのサムネイルにはできません。自分の図を見せたいときは「画像で保存」したPNGを一緒に載せてください。
- 地図上の画像カード（主要駅の見出し画像候補）は、メニューで選んだときだけ「画像で保存」と「閲覧用HTML」に入ります（初期はオフ）。共有URLには入りません。
- 共有URLには公開済みの静的サイトのURLが必要です。localhost や一時的なプレビューURLでは共有リンクを作らず、公開URLの入力を求めます。

## 分類の方法（AIなし）

1. 正規化：NFKC、小文字化、表記ゆれ（ガチャガチャ→ガチャ 等）。絵文字・URL・メール・定型フッター（記事の過半に出る段落）を除去。
2. 単語分割：ブラウザ標準の `Intl.Segmenter`（日本語辞書）。助詞・挨拶・活用語・数字・URL断片などを除外。隣接する名詞の結合語（例：再販予想）も特徴に追加。「作ってみた」「行ってきた」などの定型表現は字面一致でモチーフ語にします。
3. 特徴語：タイトル・見出し・本文を別々に TF-IDF で重み付けして正規化し、0.6 / 0.25 / 0.15 で合成（タイトル重視・長文が有利にならない）。過半の記事に出る語（例：全記事に出る「AI」）は重みを 1/4 に。
4. 路線：記事数から目安の路線数（約 0.9√N）を決め、「まだ路線のない記事を最も多く束ねられる共通語」を貪欲に選んで路線の芯にし、同じ記事群に出る共起語を路線の語彙にします。各記事は語彙の重みが最大の路線を主路線、僅差の2番目を副路線（乗換、全体の25%まで）にします。
5. 根拠のチェック：路線の他の駅と1語も共有しない駅は外し、2駅未満の路線は解散。どこにも根拠がない記事は「ひとり駅」として無理につなぎません。
6. 命名：共通語＋テンプレート（例：「アクセサリー再販線」「つくってみた線」）。根拠が弱いときは素直に「〇〇線」。
7. 意外な乗換：主路線が異なる記事の組で、全体ではめったに出ない共通語（路線語彙以外）を持つものだけを点線で結びます。
8. seed：同じ記事＋同じseedなら同じ結果。seedで路線数・芯の語の選び方・命名・接点が変わります。

性格・能力の診断、スキ数・PV・人気の推測はしません（ZIPに含まれません）。

## 路線図の描画と画面

- **配置（乗換駅を軸に広がる街）**：駅を共有する路線どうしを1つのまとまりにし、乗換の多い路線を幹にして、ほかの路線は乗換駅を通る向きを8方向から選びます（重なり・交差・密集を避け、相手の線の延長にまっすぐ続かないよう角度をつけて分かれる）。乗換駅は同じ記事の単一駅です。関係のない路線同士は線でつながず、まとまり・独立路線・ひとり駅をほぼ正方形に並べて1枚の地図にまとめます。
- **線**：水平・垂直・45度だけで結び、角は丸く。同じ区間を通る路線は少しずらして並走。あとから描く線の下地が前の線をわずかに途切れさせるので、乗換でない交差と乗換駅を区別できます。路線の始点に路線名、終点に短い終端の印。
- **読みやすさ**：背景の水彩は薄いアイボリーの膜で控えめに。駅名は地図用の短い名前（全文は記事カード）で、文字幅を実測して重ならない位置へ。30駅までは全体表示、それより多い地図は読める倍率で中心の乗換駅から始め、遠景では乗換駅・始終点の駅名を大きめに優先表示します。駅は小さくても押せる範囲は広く取っています。
- **画面（スマホ縦を優先）**：上は細いバー（タイトル・共有・メニュー）と遊び方の切り替え、下は凡例の帯と小さなズーム操作だけ。「編集」「画像で保存」「前の図」「振り返り」などはメニューに。初期表示では記事を選ばず、カードも閉じています。
- **記事カード**：駅を押すと下から小さなカード（正式タイトル・公開日・小さな路線タグ・「noteで読む」・閉じる）。「詳しく見る」か引き上げで、前の駅／次の駅、乗り換え、折りたたみの「このつながりの理由」（実際に共通する語だけを短い文で）。デモの架空URLはリンクにせず「デモ記事のためリンクはありません」と表示。iPad横画面では右側のカードに詳細まで表示。
- **演出（少しだけ）**：初回に線が引かれて駅が現れる・選んだ駅が小さく反応する・「次の駅」で地図が滑らかに移動。待たなくても操作でき、「視差効果を減らす（動きを減らす）」設定では演出なし。
- 旧い配置で保存された図は、手で動かした位置や「図を固定」がなければ開いたときに新しい配置へ直します（あれば残し、「再配置」で切り替え可能）。

## 編集・保存・書き出し

- 「編集」：駅名・原題（未設定時）・主路線/副路線・順番、路線名・色・並べ替え・削除、駅のドラッグ移動、まとめて選択で一括移動／新しい路線にする、取り消し・やり直し、図を固定、再配置。
- 路線を「固定」すると、「別の路線図にする」でもその路線は保たれます。手で変えた駅名は再生成後も保持され、編集した図は履歴に残ります（上書きしません）。
- 保存：IndexedDB に自動保存。路線図・共有設定（`project`）と本人用本文（`private`）は別ストア。
- 書き出し：編集用JSON（本文は明示選択時のみ）、SVG、PNG（駅はタップできません）、閲覧用HTML（CSS/JS/データを1ファイルに同梱、本文なし）。iOSでHTMLファイルを開けるかは環境依存のため、共有はURLが主導線です。
- ZIP再取り込み：URL/IDで照合して追加・更新を表示。編集した駅名・路線を保護し、ZIPから消えた記事は削除候補として確認します。

## 公開（GitHub Pages）

`main` に push すると `.github/workflows/pages.yml` が `tools/build-site.mjs` で公開用ファイルだけ（`index.html`・`css`・`js`・`assets/decor`）を `_site` に集めてデプロイします。
初回だけ GitHub の「Settings → Pages → Build and deployment → Source」を **GitHub Actions** にしてください（iPadのSafariから設定できます）。公開URLは通常 `https://<ユーザー名>.github.io/<リポジトリ名>/` です。

## 開発・テスト

```
npm install && npx playwright install chromium
npm test                                   # 自動テスト（Chromium・iPadエミュレーション）
NT_PRIVATE_FIXTURE=/path/to/note_export_original.zip npm test   # 実データ原本の検証（ローカル専用）
node tools/build-standalone.mjs            # 1ファイルのプレビューHTML（dist/）
```

個人のエクスポート原本・本文はリポジトリに含めません（`.gitignore` で `*.zip` と `samples_private/` を除外。`build-site` は ZIP/XML の混入を検出すると失敗します）。公開デモは架空の記事（`js/demo.js`）です。

## 確認済み事項と制約

自動テスト（`tests/run.mjs`、Chromium、iPad Pro 11 / iPhone 13 エミュレーション）で確認：

- 同梱原本：公開11件採用、下書き3件除外、公開記事のタイトル/URL欠損0、画像参照31件すべてZIP内に解決（原本はローカル検証のみ）。
- content:encoded と excerpt:encoded の混同なし。未知のstatus・予約・javascript:/data:/http: URL・タイトル欠損・日付不明でクラッシュしない。
- 壊れたZIP/XML、XMLなしZIP、圧縮率異常（ZIP爆弾）、展開サイズ上限、キャンセル。
- 1・11・100・300件（100/300件は合成データ）で駅の重なり0、NaNなし。同じseedの再現性と別seedでの変化。
- 共通語のない記事を無理につながない。
- 共有URLの往復（他アカウント・独自ドメインURL・日付・位置）、不正リンクの検証エラー、新しいブラウザ状態（IndexedDBなし）での閲覧、長さ超過時の代替導線、localhostを公開URLとして案内しない。
- 共有データ・SVG・HTML・PNGに下書き・本文・非表示記事が入らない。閲覧用HTMLが file:// で外部リクエスト0で動く。
- タッチのタップ・2本指ピンチ・縦横回転（縦は下部パネル／横は右パネル）・PNG/SVG書き出し・console error なし。

未確認：iPad / iPhone 実機での確認（Safari の実機テストは未実施。エミュレーションのみ）、iOS での PNG/HTML の保存動作（共有シート経由）、GitHub Pages 上での実際の公開URLでの往復、スクリーンリーダーでの操作。
分類の「正しさ」に唯一の正解はなく、精度の定量評価はしていません。
